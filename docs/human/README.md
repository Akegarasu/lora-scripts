# 使用 SD-Trainer

安装方法见[中文 README](../../README-zh.md)或 [English README](../../README.md)。需要让其他 agent 操作项目时，按 [MCP 连接说明](mcp.md)接入；开发者入口在[文档索引](../README.md)。

GUI 启动时默认开启 MCP，连接地址为本机同端口的 `/mcp/`，默认 `http://127.0.0.1:28000/mcp/`。GUI 设置中可即时开关并复制连接地址；选择会在下次启动时保留。外部客户端使用 Streamable HTTP 连接，浏览器与 agent 共享训练队列。

## 从数据到模型

1. 准备模型与图片。模型通常放在 `models/`，一个数据集放在 `train/<名称>/`，图片与同名 `.txt` Caption 放在一起。模型权重和数据不随项目提供。
2. 打开 Caption 工作台，选择数据目录与生成模型。先检查已有 Caption；希望生成后复核时打开“写入前复核”。默认跳过已有 Caption，覆盖或追加应按实际需要选择。
3. 在 Tag 编辑器修订文字或批量处理标签，先看预览再应用。保留备份方便回滚；文件已被外部工具修改时，回滚可能出现冲突。
4. 在训练工作台选择与底模匹配的训练器，填写模型、数据、输出位置和训练时长。常用视图提供基础项，全部视图用于查看完整能力。MOSS-Image 另见[模型配置](moss-image.md)。
5. 查看配置检查与预览，再开始训练。训练和 Caption 共享执行槽，繁忙时新任务会等待。
6. 在任务页查看状态、日志、损失/学习率曲线和输出样图。模型通常位于 `output/`；实际位置取决于填写的输出目录。

训练成功表示进程正常完成，是否符合目标仍需要看生成样图。学习率、rank、轮数等没有跨模型通用的最优值；一次调整少量变量，保留数据和配置以便比较。

## 队列与停止

同一工作区保持一个后端进程。多个浏览器和 MCP 客户端可以连接它，但不要另开第二个服务或并行脚本训练来绕过队列。

停止会终止指定任务；排队任务的终止状态可能等当前任务释放槽位后更新。服务重启保留历史，但不会恢复等待或运行中的任务；重新运行需重新提交。训练过程中更新依赖或重启 GUI 会中断任务，应待当前工作结束后进行。

## 便携版与源码版

Windows 便携版完整解压后双击 `run_gui.bat`，无需额外安装 Python、Node.js、CUDA Toolkit。默认 cu130 和回退 cu128 包的选择与驱动要求见[安装文档](../../README-zh.md#windows-nvidia-便携版)。cu128 是 CUDA/驱动组合回退，并非所有旧 GPU 的兼容包。

源码版启动后默认访问 [http://127.0.0.1:28000](http://127.0.0.1:28000)。若提示前端未构建，在 `frontend` 运行 `corepack pnpm install --frozen-lockfile` 和 `corepack pnpm run build`。更新后端依赖后重新运行安装器并重启。

## 排障

| 问题 | 检查方法 |
| --- | --- |
| 页面打不开 | 看启动终端是否报错，确认端口；不要重复打开多个后端 |
| 模型或数据不存在 | 路径是后端所在电脑的路径，核对文件是否实际存在 |
| 配置冲突 | 按检查结果修正；步数和轮数选一种，缓存会限制部分增强和文本编码器训练 |
| 显存不足 | 查看完整日志，调整 batch、分辨率或模型支持的缓存/卸载选项，再提交新任务 |
| Caption 无法运行 | 检查模型状态、依赖、网络与下载权限；已有模型也可能缺少运行依赖 |
| 曲线为空 | 任务可能还未写入事件文件，先看日志和状态 |
| 修改后结果不一致 | 保存草稿、数据版本与实际训练日志，避免同时改变多个设置 |

任务配置在 `config/runs/`，训练进程日志在 `logs/jobs/`。清理前先确认不再需要复现或回滚；备份整个工作区时，应包含数据、模型、配置及输出。
